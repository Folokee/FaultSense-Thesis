\section{Anomaly Detection}\label{sec:anomaly-detection}

\subsection{Introduction}
This section presents the anomaly detection task: distinguishing normal PV operation from fault conditions under a semi-supervised setting. It covers the explored models, their cross-validation evaluation, and concludes with an analysis of the winning design.

\subsection{Model Lineup}

\subsubsection{Bayesian Online Change-Point Detection (BOCD)}

BOCD tracks a run-length distribution, i.e. the probability that the current time step is $r$ steps into the present stationary segment. When the posterior concentrates near zero, a change point is likely.

Each feature is modelled independently with a Normal-Inverse-Gamma (NIG) conjugate prior, which places a prior over both the mean and variance of a Gaussian and allows exact Bayesian updates. The joint predictive density is the product of four univariate Student-$t$ predictives. A geometric hazard parameter $\lambda$ sets the expected run length between change points ($h = 1/\lambda$).

\paragraph{Scoring function.}
\begin{equation}
    s_t = -\log\!\left(\sum_{r=0}^{R_{\max}} R_t(r)\, p(x_t \mid r)\right),
\end{equation}
where $R_t(r)$ is the run-length posterior, $p(x_t \mid r)$ the Student-$t$ predictive density under run length $r$, and $R_{\max}=200$ a truncation limit. The run-length distribution is reset at each segment boundary to prevent state from a previous episode affecting the next.

\paragraph{Hyperparameter search space.}
BOCD is a closed-form Bayesian model; it has no gradient-based optimizer. The sole tuned parameter is \texttt{hazard\_lambda} (Table~\ref{tab:bocd-hpo}).

\subsubsection{Isolation Forest}

Isolation Forest builds an ensemble of random partitioning trees. Anomalous points require fewer splits to be isolated and therefore have shorter average path lengths from the root.

\paragraph{Scoring function.}
Each isolation tree is built by recursively selecting a random feature and a random split threshold until a point is isolated in its own leaf. The \emph{path length} $h(x)$ is the number of splits needed to isolate sample $x$ in one tree. Anomalous points, being rare and far from the bulk of the data, are separated in very few splits; normal points, densely packed with similar neighbours, require many more. The raw anomaly score is:
\begin{equation}
    s(x,\psi) = 2^{-\,\mathbb{E}[h(x)]\,/\,c(\psi)},
\end{equation}
where $\mathbb{E}[h(x)]$ is the average path length over all trees and $c(\psi) = 2H(\psi-1) - 2(\psi-1)/\psi$ is a normalisation constant equal to the expected path length of an unsuccessful binary search over $\psi$ samples ($H$ denotes the harmonic number). This normalisation makes the score comparable across different subsample sizes. A score near 1 signals an anomaly (short average path); a score near 0 signals a normal point.

Sklearn's \texttt{score\_samples} returns the negative normalised average path length directly, so lower (more negative) values indicate anomalies. Negating aligns with the project-wide convention that higher values indicate greater anomaly likelihood:
\begin{equation}
    s(x) = -\texttt{score\_samples}(x).
\end{equation}

\paragraph{Hyperparameter search space.}
Isolation Forest is a non-parametric ensemble fitted by greedy tree construction; it has no gradient-based optimizer. \texttt{n\_estimators} controls the number of trees; \texttt{max\_samples} the number of points used to build each tree; \texttt{max\_features} the fraction of features sampled per split. Table~\ref{tab:iforest-hpo} summarises the search and winning configuration.

\subsubsection{One-Class Support Vector Machine (OC-SVM)}

OC-SVM maps the training data into a high-dimensional feature space via a kernel function $k(x, x')$ and finds the tightest hyperplane that encloses the normal training data with a controlled fraction of outliers. The decision function $f_{\text{OCSVM}}(x)$ is positive for points inside the boundary (normal) and negative for points outside (anomalous). Two kernel families were explored separately: the Radial Basis Function (RBF) kernel $k(x,x') = \exp(-\gamma\|x-x'\|^2)$ and a cubic polynomial kernel.

\paragraph{Training subsample.}
The full normal training set contains 183\,801 samples. Because fitting a kernel SVM scales cubically with the number of support points, a group-stratified temporal subsample of 40\,000 samples is drawn before fitting, preserving episode diversity. Evaluation is performed on the complete val and test partitions.

\paragraph{Scoring function.}
\begin{equation}
    s(x) = -f_{\text{OCSVM}}(x),
\end{equation}
so that points outside the normal boundary score high.

\paragraph{Hyperparameter search space.}
OC-SVM is fitted by solving a quadratic program; it has no gradient-based optimizer. \texttt{nu} sets an upper bound on the fraction of training points allowed outside the boundary; \texttt{gamma} is the inverse width of the Gaussian kernel. \subsubsection{Mamba Adaptive Anomaly Transformer (MAAT)}

MAAT combines two complementary lines of work: Mamba selective state-space modeling (see Section~\ref{sec:bg-mamba}) for linear-time long-range sequence modeling, and the Anomaly Transformer association-discrepancy principle~\citep{xu2022anomaly}, which flags anomalies by comparing a data-driven series association against a Gaussian prior over adjacent time steps.

The implemented model is a variant of \citet{sellam2025maat} with three modifications:
\begin{itemize}
    \item \textbf{Token embedding}: the original \texttt{TokenEmbedding} uses a \texttt{Conv1d} with kernel size 3 and \texttt{padding\_mode=`circular'}, which wraps the end of the sequence back to the beginning. Circular padding leaks future context into the first timestep and past context into the last, violating temporal ordering. This was replaced by a pointwise \texttt{nn.Linear} projection, which embeds each timestep independently with no cross-temporal mixing at the embedding stage.
    \item \textbf{Parallel branch structure}: in the original, Mamba is applied \emph{after} the attention layer as a sequential skip connection ($\text{Mamba}(x) + x$). In our variant, both branches receive the same encoder input independently at every layer, creating two complementary temporal views: the block-local sparse attention captures short-range intra-block patterns, while the Mamba branch models long-range sequential dependencies. Running them in parallel rather than sequentially prevents either branch from conditioning on the other's output, enabling independent specialisation.
    \item \textbf{Gating}: the additive skip-connection fusion is replaced by a learned sigmoid gate on the concatenated branch outputs, giving the model per-position control over which temporal modelling strategy to emphasise.
\end{itemize}

\paragraph{Architecture.}
The encoder stack (Figure~\ref{fig:maat_architecture}) embeds each window via sinusoidal positional encoding, then passes it through $L$ layers each containing a sparse-attention branch (series association $S$ vs.\ Gaussian prior $P$) and a Mamba branch, fused by a sigmoid gate before a feed-forward sub-layer.

\begin{figure}[H]
    \centering
    \includegraphics[width=\textwidth]{figures/detection/maat_architecture.png}
    \caption{MAAT architecture.}
    \label{fig:maat_architecture}
\end{figure}

\paragraph{Training objective.}
Minimax reconstruction + association-discrepancy loss:
\begin{equation}
    \mathcal{L} = 2\mathcal{L}_{\text{rec}} + k\bigl[\mathrm{KL}(P \| S) - \mathrm{KL}(S \| P)\bigr].
\end{equation}

\paragraph{Scoring function.}
Per-step score is discrepancy-weighted reconstruction error; window score is the per-step maximum:
\begin{equation}
    A_t = \mathrm{Softmax}(-T \cdot D_t) \cdot \|x_t - \hat{x}_t\|^2, \qquad D_t = \mathrm{KL}(S\|P)+\mathrm{KL}(P\|S).
\end{equation}

\paragraph{Hyperparameter search space and winning configuration.}
The model is trained with AdamW and a cosine annealing learning-rate schedule. A two-stage HPO protocol is used: stage~1 tunes training dynamics (Table~\ref{tab:maat-s1}); stage~2 searches the architectural parameters (Table~\ref{tab:maat-s2}).

\subsubsection{Physics-Conditioned Normalizing Flow (PC-Flow)}\label{sec:ad-pcflow}

We introduce PC-Flow, a physics-conditioned normalizing flow designed for PV fault detection. A normalizing flow~\citep{rezende2015variational} is a generative model built from an exactly invertible map $f_\theta : \mathbb{R}^n \to \mathbb{R}^n$: given an input $x$ it produces a latent code $z = f_\theta^{-1}(x)$, and this transformation can be reversed exactly. This bijective structure is what distinguishes it from related generative models: unlike a variational autoencoder, which maximises a lower bound on the likelihood, the flow yields an \emph{exact} likelihood; and unlike an autoregressive model, it also learns an invertible latent representation of the input. Because the map is invertible, the exact density of any input $x$ follows from the density of its latent code $z$ through the change-of-variables formula:
\begin{equation}
    \log p(x;\theta) = \underbrace{\log p_Z(f_\theta^{-1}(x))}_{\text{log-density of the latent code}} + \underbrace{\log\left|\det\!\left(\frac{\partial f_\theta^{-1}(x)}{\partial x}\right)\right|}_{\text{log volume change of the transformation}},
\end{equation}
where $p_Z$ is a standard Gaussian base distribution, and the second term corrects for how the transformation stretches or compresses volume in different regions. The flow learns this latent representation directly from the raw signals as part of fitting the density, so anomaly scoring requires \textbf{no hand-engineered features}. To our knowledge, no prior work has applied a normalizing flow to PV anomaly detection.

\paragraph{Architecture.}
The flow is a conditional RealNVP~\citep{dinh2017realnvp}: a stack of $L$ affine coupling layers with alternating binary split masks and fixed random inter-block permutations. Each coupling block splits the input $x$ into two partitions $(x_a, x_b)$, then applies a learned scale-and-shift transformation conditioned on $(x_a, c)$:
\begin{equation}
    x_b' = x_b \cdot \exp(s(x_a, c)) + t(x_a, c),
\end{equation}
where $s$ and $t$ are produced by a small MLP with two hidden layers, and the log-determinant contribution is $\sum_i s_i(x_a, c)$. The context vector $c = [\text{irradiance},\, T_{\text{PV}}]$ encodes the current operating point. By appending $c$ to the MLP inputs at every coupling block, the flow learns a \emph{conditional} density $p(x \mid c)$ rather than a marginal: the model factors out how irradiance and temperature normally drive the measured electrical signals, so deviations from this physics-informed manifold, not absolute signal levels, are penalised. An ablation with rational-quadratic spline coupling layers~\citep{durkan2019neural} (more expressive, non-linear per-dimension transforms) is also evaluated in Table~\ref{tab:pcflow-score-abl}.

\begin{figure}[H]
    \centering
    \includegraphics[width=\textwidth]{figures/detection/pc_flow_architecture.png}
    \caption{PC-Flow architecture: conditional RealNVP with physics context $c=[\text{irr},T_{\text{PV}}]$ injected at every coupling block. Top: pipeline overview. Bottom: coupling block detail.}
    \label{fig:pcflow_architecture}
\end{figure}

\paragraph{Training objective.}
The model is trained by maximising the average negative log-likelihood (NLL) on normal training samples:
\begin{equation}
    \mathcal{L} = -\frac{1}{N}\sum_{i=1}^{N} \log p(x_i;\theta).
\end{equation}

\paragraph{Scoring function.}
The anomaly score is the negative log-likelihood: $s(x) = -\log p(x \mid c;\theta)$. Under a well-trained flow, normal samples lie in the high-probability region and score low; anomalous samples deviate from the learnt manifold and score high.

Macro PR-AUC degrades monotonically as the number of modelled features grows from 7 to 153. This is a hallmark of the \textbf{curse of dimensionality in density estimation}: the normalizing flow must model an increasingly high-dimensional normal distribution, making it harder to assign precise likelihoods to any given region. Importantly, a normalizing flow performs its \emph{own feature learning} as part of the bijective mapping; additional hand-engineered features are therefore redundant and ultimately harmful. The model extracts a latent representation that is jointly optimal for both likelihood estimation and anomaly scoring, without requiring explicit signal processing beyond the raw measurements. This result stands in deliberate contrast to the Task~B findings (Section~\ref{sec:fault-diagnosis}), where tree ensembles that \emph{cannot} learn representations benefit substantially from the same hand-crafted features.

\paragraph{Binary PR-AUC makes almost every model look excellent.}
Figure~\ref{fig:ad-binary-macro}(a) compares the six detectors on binary PR-AUC, which asks only whether a model can tell \emph{some} fault apart from normal operation. Five of the six score between 0.97 and 0.99, and even the weakest, BOCD, reaches 0.870. The reason is that this metric counts every fault sample equally, and Shadowing alone supplies most of those samples: a model that catches Shadowing scores well even if it misses the rarer faults. Taken alone, this panel is misleading: PC-Flow scores 0.972, which places it last among the five strong models and gives the false impression that it is
  the weakest.

    \label{fig:ad-binary-macro}
\end{figure}

\paragraph{The macro metric reveals the true ranking.}
Figure~\ref{fig:ad-binary-macro}(b) switches to macro PR-AUC (a metric that evaluates each fault class separately and averages the scores equally, so a rare fault carries the same weight as a common one). The picture changes completely: the models that looked tied now span 0.401 (BOCD) to 0.990 (PC-Flow), and PC-Flow rises from the bottom of the strong group to first overall. This reversal is the central result of the comparison. Binary PR-AUC hides the differences that matter for a diagnosis system, because a detector that only recognises Shadowing is blind to the three other faults it must identify. Macro PR-AUC is the metric we select on, and PC-Flow leads it.

\paragraph{One fault separates the field: Degradation.}
Figure~\ref{fig:ad-perclass} breaks every model down by fault type, one group of bars per class. Three of the four groups look nearly identical: for Short-Circuit, Open-Circuit, and Shadowing, every competitive model sits close to 1.0. These faults cause large, abrupt changes in current and power, so they are easy to separate from normal behaviour and do not decide the ranking. The fourth group, Degradation (highlighted), is where the models fan out, from 0.121 (BOCD) to 0.998 (PC-Flow). Degradation is intrinsically hard: it is a slow loss of panel efficiency with no sharp event to catch, so each measurement, taken on its own, still looks close to normal. The classical change-point and isolation methods collapse on it (BOCD 0.121, Isolation Forest 0.496), and among the deep models MAAT lags (0.753); the strongest competitors, OC-SVM (0.884) and GTBAD (0.914), close most of the gap but none reaches PC-Flow's 0.998.

PC-Flow's edge here is structural rather than incidental. It does not score a sample by how large its deviation or reconstruction error is, but by how \emph{probable} the sample is under a density of normal operation that is conditioned on the current irradiance and temperature. The model therefore judges each measurement against the behaviour expected at that exact operating point, not against a global notion of ``normal''. A small but persistent drift in the relationship between the measurements and the operating conditions lands in the low-probability tail of that conditional density and is ranked as anomalous, even when every individual signal still looks ordinary in isolation. Magnitude- and error-based scores, by contrast, can dilute such a localised drift when they aggregate over features, which is consistent with MAAT's weaker showing; PC-Flow's likelihood formulation sidesteps that aggregation, and this is what lets it rank the early-degradation samples ahead of normal operation where the other models leave the two distributions overlapping.

\paragraph{Performance--complexity trade-off.}
PC-Flow's nearest competitor is GTBAD (0.9752 against 0.990). The gap is small: GTBAD's confidence interval ($\pm$0.07) comfortably overlaps PC-Flow's, so the two are statistically close and ranking quality alone does not settle the comparison. Model size does. Figure~\ref{fig:ad-size} shows each model's parameter count, with its macro PR-AUC printed beside the bar. PC-Flow reaches the top score with 20\,124 parameters, whereas GTBAD needs 869\,769 to essentially match it, a model 43 times larger. For the Jetson Nano deployment target (Chapter~\ref{ch:deployment}), where memory use and inference time grow with parameter count, this is the deciding factor: PC-Flow delivers the same ranking quality in a model small enough to run on the edge device.
