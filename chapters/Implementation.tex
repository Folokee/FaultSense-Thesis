\subsection{Experimental Setup}\label{sec:implementation-experimental-setup}
This section summarizes the software stack and execution environment used to implement and evaluate the proposed Fault Detection and Diagnosis (FDD) pipeline. The goal is to ensure that the reported results can be reproduced from a versioned codebase, a traceable dataset state, and a documented configuration.

\paragraph{Codebase and execution contract.}
All experiments are implemented as a Python (\(\geq 3.11\)) monorepository, where each pipeline stage is exposed through a module entry point executed with a unified invocation pattern (e.g., \texttt{uv run python -m src.data.ingestion}). The \texttt{uv} build system is used as the only package and environment manager, ensuring consistent dependency resolution across local and cloud execution.

\paragraph{Configuration management.}
To minimize implicit assumptions and to enable systematic comparisons, all data and model decisions are externalized into YAML configuration files. The data configuration defines the active dataset, split policy, preprocessing options, and feature profiles, while the model configuration defines the active model lineup, hyperparameter optimization (HPO) settings, and detector-specific post-processing (e.g., anomaly threshold calibration). When multiple configuration scopes apply, parameters are resolved through a deterministic hierarchy (global defaults, dataset overrides, task directives, then profile overrides), which prevents silent overrides and simplifies run auditing.

\paragraph{Data versioning and pipeline reproducibility.}
Large artifacts (raw data, processed tables, and selected model checkpoints) are managed with Data Version Control (DVC). The end-to-end workflow is encoded as a multi-stage DVC pipeline (ingestion, splitting, preprocessing, featurization, and training), such that intermediate artifacts are regenerated from their upstream dependencies and tracked through content hashes. The DVC remote storage is hosted on DagsHub, while Git stores the lightweight \texttt{.dvc} pointers and the pipeline definition. This separation keeps the repository manageable while preserving traceability between the reported metrics and the exact data state that produced them.

\paragraph{Compute environments and execution discipline.}
Two execution environments are used depending on workload characteristics. CPU-oriented stages, including ingestion, exploratory analysis, and the classical machine learning baselines, are executed on a local machine. Deep learning training and HPO are executed on Google Colab with GPU acceleration (typically NVIDIA T4 or A100). In Colab sessions, a persistent Google Drive workspace is mounted and used as an artifacts root directory, so that Optuna studies, checkpoints, metrics, and plots survive runtime disconnections. This split avoids wasting GPU resources on CPU-bound data manipulation and focuses accelerated compute on the training loops that benefit from it.

\paragraph{Hyperparameter optimization protocol.}
% Model selection is conducted with Optuna using the Tree-structured Parzen Estimator (TPE) sampler. Classical models are tuned with fixed trial budgets, where each trial is fast and therefore pruning is not required. Deep learning models use the same Optuna interface but can additionally enable early stopping and pruning strategies, because training a single trial can span multiple epochs. For all tasks, the validation partition is the only split used for HPO decisions (metric optimization and threshold selection), while the test partition is reserved for final reporting.
Each model evaluated in this work exposes a set of parameters that govern its capacity and training dynamics (learning rate, regularization coefficients, architectural dimensions) but that training itself cannot determine. These must be selected through a separate optimization process driven by a held-out validation signal. A systematic, automated search is necessary: the number of candidate configurations is too large for manual exploration, and deep learning models in particular carry non-trivial trial costs that penalize exhaustive strategies.

Optimization is performed using Optuna \citep{akiba2019optuna} with the Tree-structured Parzen Estimator (TPE) sampler. Rather than enumerating a predefined grid of configurations as grid search does \citep{bergstra2012random}, or evolving a population of candidates as genetic algorithms require, TPE builds a probabilistic model of the objective from the history of completed trials and focuses subsequent sampling on the regions associated with good outcomes. This sequential, model-guided search reaches competitive configurations in far fewer trials than either exhaustive or population-based alternatives, which is decisive when individual trials involve full training runs of deep architectures.

Each HPO study runs on the fixed original train/val split and completes before the K-fold cross-validation begins, so the winning configuration is fixed for all folds. The test partition is invisible throughout. The optimization objective is the validation macro per-class PR-AUC for anomaly detection and the validation macro F1 for fault classification, consistent with the headline metrics of Section~\ref{sec:evaluation-methodology}. Among configurations whose scores fall within one standard deviation of each other, the simpler configuration is preferred as a tiebreaker.

The pruning strategy is adapted to trial cost. For classical ML models, no pruner is applied: trials are inexpensive and no intermediate epoch-level signal is available. For deep learning models, a Median pruner is added: a trial is terminated when its intermediate validation score falls below the median of all completed trials at the same epoch, after a warmup period during which pruning is suspended. Within-trial early stopping patience scales with the trial epoch budget, preventing premature termination on short trial budgets.


\paragraph{Experiment tracking and artifacts.}
All runs are tracked with MLflow and logged to a centralized DagsHub tracking server. Each run records the active dataset and split identifier, the selected feature profile, the final HPO parameters, and the computed validation and test metrics. In addition, lightweight artifacts are stored alongside metrics, including serialized preprocessing objects (e.g., scalers), model files (\texttt{.joblib} for classical models and checkpoints for deep learning), and diagnostic figures such as PR curves, score histograms, and confusion matrices. This tracking discipline supports direct comparison across the anomaly detection and fault classification experiments.

\subsection{Task Formulation and Methodology}
Semi-supervised learning is a machine learning technique that trains models using a small amount of labeled data and a large amount of unlabeled data.
The anomaly detection task can be seen as a semi-supervised learning problem, this approach is ideal for our case because it allows us to leverage the limited labeled data available.
The various methods discussed below follow a common framework:
\begin{itemize}
    \item Train a model on normal-behavior data to extract generalizable signatures of normal operation.
    \item Derive a scoring function that measures deviation from normality—higher scores correspond to a higher likelihood of an anomaly.
    \item Calibrate a threshold from this scoring function. During inference, the model computes the score and flags the current state as anomalous if the score exceeds the threshold.
\end{itemize}

\subsubsection{Bayesian Online Change Point Detection (BOCD)}

The Bayesian Online Change Point Detection (BOCD) detector models each feature independently using a Normal-Inverse-Gamma (NIG) conjugate prior, and forms a joint multivariate predictive density as the product of univariate Student-$t$ predictives. The sequential run-length posterior is then used to compute a predictive mixture likelihood, which decreases sharply when the observed sequence becomes unlikely under the current run.

\paragraph{} As in the other classical baselines, inputs are standardized using a \texttt{StandardScaler} fitted on the training partition. During \texttt{fit}, the NIG prior parameters are initialized from the training statistics, with $\mu_0$ set to the per-feature training mean and $\beta_0$ set to $\alpha_0$ times the per-feature training variance.

\paragraph{} BOCD maintains a run-length distribution with a geometric hazard prior controlled by \texttt{hazard\_lambda} (denoted $\lambda$), where the changepoint probability is $h=1/\lambda$. The run-length posterior is truncated to $R_{\mathrm{trunc}}=200$ to keep memory and compute bounded by $\mathcal{O}(R_{\mathrm{trunc}}\times F)$.

\paragraph{} The anomaly score is defined as the negative log predictive likelihood under the run-length mixture. Let $R_t(r)$ be the run-length posterior at time $t$ and $p(x_t\mid r)$ the corresponding predictive density; the score is computed as:
\begin{equation}
    s_t = -\log\left(\sum_{r=0}^{R_{\mathrm{trunc}}} R_t(r)\, p(x_t\mid r)\right).
\end{equation}

\paragraph{} To avoid state carryover across operational gaps, scoring is group-aware: the run-length distribution is reset at each segment boundary (\texttt{episode\_id} for Path~A and \texttt{operating\_day\_id} for Path~B). The first score in every segment is therefore computed from the global prior fitted on the training partition.

\paragraph{} When hyperparameter optimization is enabled, Optuna is used with the TPE sampler for 35 trials, tuning only \texttt{hazard\_lambda}.

\subsubsection{Mamba Adaptive Anomaly Transformer (MAAT)}
The Mamba Adaptive Anomaly Transformer (MAAT) is a semi‑supervised anomaly detector for multivariate PV time series that jointly considers reconstruction fidelity and temporal association consistency. The architecture, shown in Fig.~\ref{impl:fig:maat_architecture}, embeds an input window into a model‑dimension representation using a linear projection, sinusoidal positional encoding, and dropout. An encoder of $L$ stacked layers processes the sequence, each layer containing two parallel branches: a sparse anomaly‑attention branch that learns block‑local temporal associations (series association) alongside a fixed Gaussian prior, and a Mamba state‑space branch that models long‑range dependencies with linear complexity. Their outputs are fused via a learned sigmoid gate, followed by a feed‑forward network. A final linear projection reconstructs the input.

MAAT is trained with a minimax loss that balances the reconstruction mean squared error against a signed Kullback–Leibler divergence between the learned and prior associations, forcing the series association to deviate from local continuity on normal data. At inference, anomaly scores combine the association discrepancy and reconstruction error through temperature‑weighted summation; the window‑level score is the maximum over time, ensuring that anomalies are flagged only when both temporal dynamics and reconstruction quality break down.

\subsubsection{GTBAD: Gated Transformer-BiLSTM Anomaly Detector}

The GTBAD model is a simple sequence-to-sequence pipeline: an input projection maps the feature vector to a model 
dimension $d_{\text{model}} = 64$, a fixed sinusoidal positional encoding is added, and a 3‑layer Transformer encoder with 2 attention heads captures per‑step dependencies. The encoded representation is decoded by a single‑layer bidirectional LSTM with a hidden size of 32, followed by dropout ($p=0.1$) and a linear layer that projects
 back to the original input space. Because the window length is set to 1, each time step is processed independently; the model learns to reconstruct normal operating patterns and flags anomalies via reconstruction error\citep{GTBADGVSAOTransformerBiLSTMbasedTimeseries2026}. \subsubsection{PC-Flow (Physics-Conditioned Normalizing Flow)}

PC-Flow is a conditional normalizing flow: a bijective generative model that learns the conditional density $p(\mathbf{x} \mid \mathbf{c})$ of the normal-class feature vector $\mathbf{x}$ given the physics operating context $\mathbf{c} = (\texttt{irr}, \texttt{pvt})$. The anomaly score for a test sample is the negative conditional log-likelihood:
\[
    s(\mathbf{x} \mid \mathbf{c}) = -\log p(\mathbf{x} \mid \mathbf{c}) = \frac{1}{2}\|\mathbf{z}\|^2 + \frac{D}{2}\log(2\pi) - \sum_{k=1}^{K} \log|\det J_k|,
\]
where $\mathbf{z} = f(\mathbf{x}; \mathbf{c})$ is the latent representation under the invertible transformation $f$, and $J_k$ is the Jacobian of the $k$-th coupling block. Higher scores indicate samples that are unlikely under the learned normal-class conditional distribution, and therefore more anomalous.

\paragraph{} Reconstruction-based detectors score a sample by its mean squared error $\mathrm{MSE}(\mathbf{x}, \hat{\mathbf{x}}) = \frac{1}{D}\sum_{i=1}^{D}(x_i - \hat{x}_i)^2$. This averaging over all $D$ feature dimensions has two structural limitations: a subtle fault signal localized in one or two channels, such as the inter-string current divergence that characterizes the degradation class, is diluted by reconstruction accuracy on the remaining non-informative dimensions, and a deep bottleneck that learns to reconstruct normal-class data can generalize to mild anomalies, assigning them a low anomaly score. The normalizing flow avoids both failure modes: the log-likelihood is computed exactly without a lossy bottleneck, and the score accounts for the full multivariate structure of the conditional density rather than averaging error independently across dimensions.

\paragraph{} The operating context $\mathbf{c}$ is fed into every coupling block's scale-and-translate network, so the flow models $p(\mathbf{x} \mid \mathbf{c})$ directly: a sample is flagged as anomalous if its electrical state is unlikely given its irradiance and temperature. This formulation captures the diagnostic question in PV fault detection precisely. PC-Flow is stateless — each measurement is scored independently without recurrence, attention over past windows, or temporal memory — which simplifies the deployment contract to a single feature vector in, a single scalar score out, requiring no warm-up period or history buffer.

\paragraph{Architecture.} PC-Flow consists of $K = 4$ conditional affine coupling blocks. Each block splits the feature vector into two halves using a fixed binary alternating mask, computes a scale-and-translate pair $(\mathbf{s}, \mathbf{t}) = \mathrm{MLP}([\mathbf{x}_a; \mathbf{c}])$ conditioned on the pass-through half and the physics context, applies the invertible transformation $\mathbf{x}_b' = \mathbf{x}_b \odot \exp(\mathbf{s}) + \mathbf{t}$, and applies a fixed random permutation so that all feature dimensions mix across the depth of the stack. The log-scale is bounded with $\tanh(\mathbf{s}) \cdot 2$ for training stability. The coupling MLP hidden dimension is 32 with GELU activations, and the scale-and-translate head is zero-initialized so each block starts as the identity transformation. The total parameter count is approximately 23,000, and the base distribution is a standard isotropic Gaussian. The \texttt{plus\_physics} profile with 15 modeled dimensions and 2 context dimensions was used as the input representation.

\paragraph{Training and HPO.} The training objective is the mean negative conditional log-likelihood on normal-class training samples. A StandardScaler fit on the normal-class training rows is applied before the flow. No fault-labeled data enters the training objective. Hyperparameter optimization uses Optuna with the TPE sampler, maximizing the fold-average validation macro per-class PR-AUC with the GPD threshold calibrated on the train-normal NLL scores. The search space covers the number of coupling blocks $K \in \{2, 4, 6, 8\}$, hidden dimension $d_h \in \{16, 32, 64\}$, batch size, learning rate, and weight decay. Early stopping monitors the validation macro per-class PR-AUC and checkpoints the configuration at its peak.

\subsection{Discussion and Winning Model}

The per‑class results reveal clear differences in how each model ranks and separates fault states from normal operation, beyond the aggregate metrics reported earlier.

The \textbf{One‑Class SVM} delivers excellent overall ranking (PR‑AUC 0.9977) and strong per‑class PR‑AUC values, exceeding 0.99 for Short‑Circuit, Open‑Circuit, and Shadowing. The RBF kernel captures the normal data envelope effectively, and the calibrated threshold yields high F1 scores. However, the Degradation class PR‑AUC (0.8993) indicates that the distance‑based score struggles to rank subtle degradation patterns as consistently as the other faults.

\textbf{Isolation Forest} achieves near‑perfect ranking for Open‑Circuit (PR‑AUC 1.0000) and very good results for Shadowing (0.9881), but its performance on Degradation drops sharply (PR‑AUC 0.5645, F1 0.4250). The axis‑parallel splits of the isolation trees appear insufficient to isolate the multivariate signature of degradation anomalies, making the score unreliable for that fault type.

\textbf{BOCD} shows a marked weakness across all fault classes except Shadowing, with PR‑AUC values below 0.31 for Short‑Circuit, Degradation, and Open‑Circuit. The sequential change‑point model, built on univariate Normal–Inverse‑Gamma predictives, does not adapt well to the static PV context and produces many false positives, as reflected in very low precision. Its strength lies only in the abundant Shadowing class, but even there the ranking quality (PR‑AUC 0.8110) is below other models.

\textbf{GTBAD}, a Transformer–BiLSTM reconstruction model, yields respectable deployment metrics (macro F1 0.9156) but its per‑class ranking quality is extremely uneven. For Short‑Circuit and Degradation the PR‑AUC values are near chance level (0.0432 and 0.0410), while Open‑Circuit (0.9890) and Shadowing (0.8291) are well ranked. This indicates that the reconstruction error works well for large‑scale anomalies (Open‑Circuit, Shadowing) but fails to provide a meaningful ordering for the more subtle fault types, likely because the model overfits to the dominant normal patterns and does not amplify the signal of those faults.

\textbf{PC-Flow} (Physics-Conditioned Normalizing Flow) delivers consistently high ranking quality across all fault classes under a rigorous 5-fold episode-stratified cross-validation protocol. Its per-class PR-AUC values are 1.000 (Short-Circuit and Open-Circuit), 0.973 (Degradation), and 0.985 (Shadowing), with a worst-class PR-AUC of 0.968 and a binary PR-AUC of 0.989. The exact conditional log-likelihood avoids the limitations of reconstruction-based scoring: the score accounts for the full multivariate structure of the conditional density rather than averaging error independently across dimensions, and the absence of a lossy bottleneck ensures that subtle fault signatures such as the inter-string current divergence of the degradation class are not diluted by non-informative dimensions. The stateless architecture of fewer than 23,000 parameters, accepting a single feature vector and producing a single scalar score, directly targets the 50~ms edge inference budget without recurrence or temporal memory overhead. The physics conditioning on irradiance and module temperature provides the inductive bias necessary to model normal PV behaviour as a conditional density, making the negative log-likelihood a robust and interpretable anomaly score.

\section{Fault Diagnosis Implementation and Results}
\subsection{Task Formulation and Methodology}

\paragraph{Problem definition.}
Let $x \in \mathbb{R}^F$ denote a feature vector computed from a time segment of PV electrical and meteorological signals, and let $y \in \{0,\dots,C-1\}$ denote the corresponding fault label among $C$ classes. The diagnosis task consists in learning a classifier $f_\theta$ that maps $x$ to a class probability vector $\hat{p}(y\mid x)$, and predicts the most likely class $\hat{y}=\arg\max_c \hat{p}(c\mid x)$. Because fault classes can be imbalanced in realistic PV logs, the training and evaluation protocol must account for class frequency differences.

\subsection{Discussion and Winning Model}

The three tree‑based classifiers all achieve high overall accuracy and macro‑averaged F1 scores, but their per‑class behaviour reveals important differences in how they handle the most challenging fault categories.

\textbf{LightGBM} delivers strong performance on Degradation (F1 0.9098, PR‑AUC 0.9875) and near‑perfect metrics for Open‑Circuit and Shadowing. However, the Short‑Circuit class remains the hardest to separate: the PR‑AUC of 0.9357 and F1 of 0.8945 indicate that the histogram‑based boosting model occasionally confuses short‑circuit signatures with other faults. While the balanced class‑weighting policy prevents catastrophic minority neglect, the ranking quality for this safety‑critical class is the weakest among the three candidates.

\textbf{ExtraTrees} attains the highest macro‑averaged F1 (0.9611) and perfect recall/precision for Open‑Circuit. Its extremely randomised splits yield robust probability estimates, and the F1 for Short‑Circuit (0.9520) is slightly above that of CatBoost. Nevertheless, the PR‑AUC for Short‑Circuit (0.9483) is lower than CatBoost’s, suggesting that the randomised ensemble produces a less reliable ordering of the predicted probabilities for the minority fault. In a diagnosis setting where a missed short‑circuit has severe operational consequences, a higher PR‑AUC for that class is often more valuable than a marginal gain in macro F1.

\textbf{CatBoost} stands out by achieving the highest PR‑AUC for Short‑Circuit (0.9632), a clear improvement over both LightGBM (0.9357) and ExtraTrees (0.9483). This reflects the symmetric‑tree ordered‑boosting strategy, which reduces prediction shift and yields well‑calibrated scores that separate short‑circuit examples from other classes more effectively. At the same time, CatBoost maintains perfect recall for Short‑Circuit and Open‑Circuit, ensuring that no true fault of those types is missed. The per‑class F1 values are highly competitive (Short‑Circuit 0.9509, Open‑Circuit 0.9979, Shadowing 0.9957) and the weighted OvR PR‑AUC ties with ExtraTrees at 0.9979. The only noticeable drop occurs for Degradation, where the PR‑AUC (0.9586) is lower than LightGBM’s; however, the superior ranking on the most safety‑critical class compensates for this, and the macro F1 of 0.9565 remains very close to the best value.

\section{Conclusion}
This chapter implemented and evaluated a two-stage Fault Detection and Diagnosis (FDD) pipeline on the Costa PV dataset. For anomaly detection, the \textbf{Physics-Conditioned Normalizing Flow (PC-Flow)} was selected as the winning model because it delivers consistently high ranking quality across all fault classes (per-class PR-AUC $\geq$ 0.973, worst-class PR-AUC 0.968) under 5-fold episode-stratified cross-validation, ensuring reliable anomaly scoring regardless of the chosen threshold. For fault diagnosis, \textbf{CatBoost} emerged as the preferred classifier, offering the best PR-AUC for the safety-critical Short-Circuit class while maintaining perfect recall on that class and near-perfect metrics overall (macro F1 0.9565). Together, PC-Flow and CatBoost form a coherent FDD pipeline: PC-Flow provides sensitive, well-ordered anomaly alarms through exact conditional density estimation, and CatBoost gives precise, trustworthy fault identification once an alarm is raised. Both models are fully reproducible under the versioned experimental infrastructure, and their selection prioritises operational safety and per-class reliability over aggregate metrics alone.
