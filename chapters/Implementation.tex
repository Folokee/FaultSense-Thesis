\subsection{Experimental Setup}\label{sec:implementation-experimental-setup}
This section summarizes the software stack and execution environment used to implement and evaluate the proposed Fault Detection and Diagnosis (FDD) pipeline. The goal is to ensure that the reported results can be reproduced from a versioned codebase, a traceable dataset state, and a documented configuration.

\paragraph{Codebase and execution contract.}
All experiments are implemented as a Python (\(\geq 3.11\)) monorepository, where each pipeline stage is exposed through a module entry point executed with a unified invocation pattern (e.g., \texttt{uv run python -m src.data.ingestion}). The \texttt{uv} build system is used as the only package and environment manager, ensuring consistent dependency resolution across local and cloud execution.

\paragraph{Configuration management.}
To minimize implicit assumptions and to enable systematic comparisons, all data and model decisions are externalized into YAML configuration files. The data configuration defines the active dataset, split policy, preprocessing options, and feature profiles, while the model configuration defines the active model lineup, hyperparameter optimization (HPO) settings, and detector-specific post-processing (e.g., anomaly threshold calibration). When multiple configuration scopes apply, parameters are resolved through a deterministic hierarchy (global defaults, dataset overrides, task directives, then profile overrides), which prevents silent overrides and simplifies run auditing.

\paragraph{Data versioning and pipeline reproducibility.}
Large artifacts (raw data, processed tables, and selected model checkpoints) are managed with Data Version Control (DVC). The end-to-end workflow is encoded as a multi-stage DVC pipeline (ingestion, splitting, preprocessing, featurization, and training), such that intermediate artifacts are regenerated from their upstream dependencies and tracked through content hashes. The DVC remote storage is hosted on DagsHub, while Git stores the lightweight \texttt{.dvc} pointers and the pipeline definition. This separation keeps the repository manageable while preserving traceability between the reported metrics and the exact data state that produced them.

\paragraph{Compute environments and execution discipline.}
Two execution environments are used depending on workload characteristics. CPU-oriented stages, including ingestion, exploratory analysis, and the classical machine learning baselines, are executed on a local machine. Deep learning training and HPO are executed on Google Colab with GPU acceleration (typically NVIDIA T4 or A100). In Colab sessions, a persistent Google Drive workspace is mounted and used as an artifacts root directory, so that Optuna studies, checkpoints, metrics, and plots survive runtime disconnections. This split avoids wasting GPU resources on CPU-bound data manipulation and focuses accelerated compute on the training loops that benefit from it.

\paragraph{Hyperparameter optimization protocol.}
Model selection is conducted with Optuna using the Tree-structured Parzen Estimator (TPE) sampler. Classical models are tuned with fixed trial budgets, where each trial is fast and therefore pruning is not required. Deep learning models use the same Optuna interface but can additionally enable early stopping and pruning strategies, because training a single trial can span multiple epochs. For all tasks, the validation partition is the only split used for HPO decisions (metric optimization and threshold selection), while the test partition is reserved for final reporting.

\paragraph{Experiment tracking and artifacts.}
All runs are tracked with MLflow and logged to a centralized DagsHub tracking server. Each run records the active dataset and split identifier, the selected feature profile, the final HPO parameters, and the computed validation and test metrics. In addition, lightweight artifacts are stored alongside metrics, including serialized preprocessing objects (e.g., scalers), model files (\texttt{.joblib} for classical models and checkpoints for deep learning), and diagnostic figures such as PR curves, score histograms, and confusion matrices. This tracking discipline supports direct comparison across the anomaly detection (Task~A) and fault classification (Task~B) experiments.

\paragraph{Random seeds and repeated runs.}
To control stochasticity, experiments are executed with predefined random seeds. A canonical single-run seed is used for rapid iteration, while a small multi-seed suite is used when estimating the stability of reported metrics. Unless stated otherwise, training and evaluation follow the leakage-aware splitting protocol described in Section~\ref{sec:implementation-splitting}.

\subsection{Task Formulation and Methodology}
Semi-supervised learning is a machine learning technique that trains models using a small amount of labeled data and a large amount of unlabeled data.
The anomaly detection task can be seen as a semi-supervised learning problem, this approach is ideal for our case because it allows us to leverage the limited labeled data available.
The various methods discussed below follow a common framework:
\begin{itemize}
    \item Train a model on normal-behavior data to extract generalizable signatures of normal operation.
    \item Derive a scoring function that measures deviation from normality—higher scores correspond to a higher likelihood of an anomaly.
    \item Calibrate a threshold from this scoring function. During inference, the model computes the score and flags the current state as anomalous if the score exceeds the threshold.
\end{itemize}

This section describes the implementation of the anomaly detection model lineup and the hyperparameter optimization (HPO) protocol used to select the final configurations. The implementation follows a shared experimental contract across models: a unified split interface, a consistent scoring convention (higher scores indicate higher anomaly likelihood), a threshold calibration stage executed on validation scores, and a common reporting suite that includes prevalence-aware metrics.

\subsubsection{One-Class Support Vector Machine (OC-SVM)}
As previously described in Subsection~\ref{subsec:svm}, SVM is mainly a supervised learning algorithm,
but the One-Class SVM (OC-SVM) variant is designed for semi-supervised anomaly detection by identifying the smallest hyperplane
that encloses the normal data in the feature space.
Two kernel functions were explored: RBF and polynomial.
\paragraph{} Optuna was used for hyperparameter optimization with 35 trials and Macro F1 as the objective metric, tuning the kernel-specific parameters.
\paragraph{} The scoring function is the negative distance to the separating hyperplane, so that higher scores indicate higher anomaly likelihood.
\paragraph{Results}

\subsubsection{Bayesian Online Change Point Detection (BOCD)}

The Bayesian Online Change Point Detection (BOCD) detector models each feature independently using a Normal-Inverse-Gamma (NIG) conjugate prior, and forms a joint multivariate predictive density as the product of univariate Student-$t$ predictives. The sequential run-length posterior is then used to compute a predictive mixture likelihood, which decreases sharply when the observed sequence becomes unlikely under the current run.

\paragraph{} As in the other classical baselines, inputs are standardized using a \texttt{StandardScaler} fitted on the training partition. During \texttt{fit}, the NIG prior parameters are initialized from the training statistics, with $\mu_0$ set to the per-feature training mean and $\beta_0$ set to $\alpha_0$ times the per-feature training variance.

\paragraph{} BOCD maintains a run-length distribution with a geometric hazard prior controlled by \texttt{hazard\_lambda} (denoted $\lambda$), where the changepoint probability is $h=1/\lambda$. The run-length posterior is truncated to $R_{\mathrm{trunc}}=200$ to keep memory and compute bounded by $\mathcal{O}(R_{\mathrm{trunc}}\times F)$.

\paragraph{} The anomaly score is defined as the negative log predictive likelihood under the run-length mixture. Let $R_t(r)$ be the run-length posterior at time $t$ and $p(x_t\mid r)$ the corresponding predictive density; the score is computed as:
\begin{equation}
    s_t = -\log\left(\sum_{r=0}^{R_{\mathrm{trunc}}} R_t(r)\, p(x_t\mid r)\right).
\end{equation}

\paragraph{} To avoid state carryover across operational gaps, scoring is group-aware: the run-length distribution is reset at each segment boundary (\texttt{episode\_id} for Path~A and \texttt{operating\_day\_id} for Path~B). The first score in every segment is therefore computed from the global prior fitted on the training partition.

\paragraph{} When hyperparameter optimization is enabled, Optuna is used with the TPE sampler for 35 trials, tuning only \texttt{hazard\_lambda}.

\subsubsection{Mamba Adaptive Anomaly Transformer (MAAT)}
The proposed Mamba Adaptive Anomaly Transformer (MAAT) is a deep semi-supervised anomaly detector designed for multivariate PV time-series data. The architecture combines sparse anomaly attention with a parallel Mamba state-space branch and a minimax association learning objective. Unlike classical reconstruction-based autoencoders, MAAT jointly models reconstruction fidelity and temporal association consistency, allowing the detector to identify subtle deviations in temporal dynamics even when reconstruction error alone remains low.

\paragraph{} The overall architecture is illustrated in Fig.~\ref{fig:maat_architecture}. The model receives an input window
\[
x \in \mathbb{R}^{B \times W \times F},
\]
where $B$ denotes the batch size, $W$ the temporal window length, and $F$ the number of features. The input is first transformed through a \texttt{DataEmbedding} module composed of:
\begin{itemize}
    \item a linear token embedding projecting $F \rightarrow d_{\text{model}}$,
    \item a sinusoidal positional embedding,
    \item and a dropout layer applied after summation.
\end{itemize}

The resulting representation is:
\[
H^{(0)} \in \mathbb{R}^{B \times W \times d_{\text{model}}}.
\]

\begin{figure}[H]
    \centering
    \includegraphics[width=\textwidth]{figures/detection/maat-architecture.png}
    \caption{Overall architecture of the proposed MAAT model combining sparse anomaly attention and Mamba state-space modeling.}
    \label{fig:maat_architecture}
\end{figure}

\paragraph{} The encoder consists of $L$ stacked \texttt{EncoderLayer} blocks. Each layer contains two parallel temporal modeling branches: a sparse anomaly-attention branch and a Mamba state-space branch. Their outputs are fused through a learned gating mechanism before being processed by a position-wise feed-forward network.

\paragraph{} The anomaly-attention branch computes two distinct temporal association matrices:
\begin{itemize}
    \item the \emph{series association} $S$, learned through block-local sparse self-attention,
    \item and the \emph{prior association} $P$, defined by a Gaussian kernel parameterized by learned variance terms.
\end{itemize}

Given queries $Q$, keys $K$, and values $V$, the series association is computed as:

\begin{equation}
S = \mathrm{Softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right),
\end{equation}

where attention is restricted to positions within the same temporal block of size \texttt{block\_size}. This sparse attention mechanism constrains the model to learn local temporal dependencies characteristic of normal PV operation.

\paragraph{} In parallel, the prior association is modeled using a Gaussian kernel:

\begin{equation}
P_{i,j} \propto
\exp\left(
-\frac{|i-j|^2}{2\sigma_i^2}
\right),
\end{equation}

where $\sigma_i$ is learned dynamically through a dedicated linear projection layer. The prior distribution represents an inductive bias describing expected local temporal continuity under normal operating conditions.

\paragraph{} Unlike standard attention mechanisms, only the learned series association $S$ is used for value aggregation:

\begin{equation}
\mathrm{Attention}(Q,K,V) = S \cdot V.
\end{equation}

The Gaussian prior $P$ is used exclusively for discrepancy-based anomaly scoring and minimax optimization.

\paragraph{} Parallel to the attention branch, each encoder layer contains a Mamba selective state-space model (SSM) branch. The Mamba block models long-range temporal dependencies with linear computational complexity, enabling efficient processing of long PV sequences while preserving sequential dynamics that may not be captured by local attention alone.

\paragraph{} The outputs of the attention and Mamba branches are fused through a learned gating mechanism:

\begin{equation}
G = \sigma\left(
W_g [H_{\mathrm{mamba}} \, \| \, H_{\mathrm{attn}}]
\right),
\end{equation}

\begin{equation}
H_{\mathrm{fused}}
=
G \odot H_{\mathrm{mamba}}
+
(1-G) \odot H_{\mathrm{attn}},
\end{equation}

where $\sigma(\cdot)$ denotes the sigmoid activation and $\odot$ the element-wise product. This mechanism allows the network to adaptively determine whether local attention-based patterns or long-range state-space dynamics should dominate for a given temporal context.

\paragraph{} The fused representation is processed through residual connections, Layer Normalization, and a position-wise feed-forward network implemented using $1\times1$ convolutions with GELU activation. After the final encoder layer, a linear projection reconstructs the original feature space:

\[
\hat{x} \in \mathbb{R}^{B \times W \times F}.
\]

\paragraph{} MAAT is trained using a minimax objective combining reconstruction error and association discrepancy. Let $\mathcal{L}_{\mathrm{rec}}$ denote the reconstruction mean squared error and $\mathrm{KL}(\cdot\|\cdot)$ the Kullback--Leibler divergence. The training objective is defined as:

\begin{equation}
\mathcal{L}
=
2\mathcal{L}_{\mathrm{rec}}
+
k
\left[
\mathrm{KL}(P \| S)
-
\mathrm{KL}(S \| P)
\right],
\end{equation}

where $k$ controls the balance between reconstruction and association learning. This minimax formulation encourages the learned series associations to diverge maximally from the Gaussian prior on normal data, thereby amplifying deviations during anomalous conditions.

\paragraph{} During inference, anomaly scores are computed using both reconstruction error and association discrepancy. The discrepancy between the series and prior associations is first estimated as:

\begin{equation}
D_t
=
\mathrm{KL}(S \| P)
+
\mathrm{KL}(P \| S).
\end{equation}

The discrepancy is transformed into temporal importance weights using a temperature-scaled softmax:

\begin{equation}
w_t
=
\mathrm{Softmax}(-T D_t),
\end{equation}

where $T$ is the temperature hyperparameter. The final timestep-level anomaly score is then computed as:

\begin{equation}
A_t
=
w_t \cdot \|x_t - \hat{x}_t\|^2.
\end{equation}

Window-level anomaly scores are obtained by taking the maximum score over the temporal dimension. This formulation ensures that anomalies are detected only when both temporal associations are disrupted and reconstruction quality deteriorates.

\paragraph{} MAAT is trained exclusively on healthy operating data, following a semi-supervised anomaly detection paradigm. Hyperparameter optimization is performed using Optuna with a two-stage Tree-structured Parzen Estimator (TPE) search strategy. The first stage optimizes training-related parameters such as learning rate, dropout, temperature, and reconstruction weight, while the second stage optimizes architectural parameters including window size, block size, embedding dimension, number of heads, encoder depth, and feed-forward dimension.

\paragraph{} To ensure consistent thresholding across all evaluated baselines, the anomaly threshold is calibrated using a Peaks-Over-Threshold (POT) Generalized Pareto Distribution (GPD) fitted on validation-normal scores.

\section{Fault Diagnosis Implementation and Results}
\subsection{Task Formulation and Methodology}

\paragraph{Problem definition.}
Let $x \in \mathbb{R}^F$ denote a feature vector computed from a time segment of PV electrical and meteorological signals, and let $y \in \{0,\dots,C-1\}$ denote the corresponding fault label among $C$ classes. The diagnosis task consists in learning a classifier $f_\theta$ that maps $x$ to a class probability vector $\hat{p}(y\mid x)$, and predicts the most likely class $\hat{y}=\arg\max_c \hat{p}(c\mid x)$. Because fault classes can be imbalanced in realistic PV logs, the training and evaluation protocol must account for class frequency differences.

\paragraph{Inputs.}
Diagnosis is performed on pre-engineered tabular features rather than on raw time-series windows. Feature computation is executed upstream in the preprocessing and featurization pipeline, and the classification stage consumes the resulting feature tables. This design keeps the diagnosis models lightweight and enables transparent analysis of feature contributions.

\paragraph{Evaluation protocol and metrics.}
The dataset is split into training, validation, and test partitions using the same leakage-aware splitting protocol described in Section~\ref{sec:implementation-splitting}. Model selection is primarily driven by macro-averaged F1-score (macro F1), which assigns equal weight to each class and is therefore sensitive to minority-class performance. For completeness, additional metrics are reported, including overall accuracy, balanced accuracy, macro and weighted precision/recall/F1, and one-vs-rest (OvR) precision--recall AUC values (weighted and per-class).

\subsubsection{LightGBM Classifier}

% LightGBM is a gradient-boosting framework that builds an ensemble of decision trees sequentially, where each new tree focuses on correcting the errors made by the current ensemble. In the diagnosis setting, the model learns non-linear decision boundaries over engineered features and can capture complex interactions between electrical indicators and contextual variables. LightGBM is selected as the default classifier because it provides a strong accuracy--efficiency trade-off on tabular data and scales well during hyperparameter search.

% To mitigate class imbalance, the training procedure applies automatic class weighting so that minority fault classes receive proportionally higher penalty when misclassified. The gradient‑boosting classifier is built on \texttt{lightgbm.LGBMClassifier}, a histogram‑based algorithm that provides fast training and low memory usage.
The model is configured with the following fixed parameters:

\begin{itemize}

\subsubsection{CatBoost Classifier}

% CatBoost is another gradient-boosting method that uses symmetric trees and an ordered boosting strategy designed to reduce prediction shift during training. Although CatBoost is particularly known for robust handling of categorical features, it also performs competitively on fully numerical feature sets and offers stable optimization behavior. In this project, CatBoost is implemented as an alternative to LightGBM within the same training harness.

% The model is tuned with the same primary objective (macro F1) and the same validation modes. Class imbalance is handled through the algorithm's native balanced class-weighting mechanism. When enabled, the same sigmoid calibration stage is applied to CatBoost probability outputs using validation data.
CatBoost is integrated via \texttt{catboost.CatBoostClassifier}, employing symmetric trees and ordered target encoding.
The classifier is initialised with the following fixed parameters:

\begin{itemize}
    \item \texttt{loss\_function = "MultiClass"} – multi‑class cross‑entropy.
    \item \texttt{eval\_metric = "TotalF1:average=Macro"} – macro‑averaged F1 is tracked natively during training, removing the need for an external evaluation step inside the objective function.
    \item \texttt{auto\_class\_weights = "Balanced"} – CatBoost’s built‑in automatic class balancing, analogous to LightGBM’s \texttt{class\_weight="balanced"}.
    \item \texttt{random\_seed} – set to the global seed.
    \item \texttt{thread\_count} – number of threads, directly assigned from the resolved thread count (no \texttt{n\_jobs}/\texttt{num\_threads} separation).
\end{itemize}

Hyper‑parameter search uses the same Optuna framework (50 trials, TPE sampler) or falls back to the midpoint of each range when optimisation is disabled.
The search space (Table~\ref{tab:catboost_hp_space}) contains log‑uniform, integer, float, and categorical domains; the suggestion parser interprets the explicit \texttt{\{type, low, high\}} specification accordingly, applying step sizes for integers and logarithmic sampling where indicated.

\subsubsection{ExtraTrees Classifier}

% ExtraTrees (Extremely Randomized Trees) is an ensemble method that averages the predictions of many decision trees built with strong randomization. In contrast to boosting, trees in ExtraTrees are trained largely independently, and randomness is injected by selecting split thresholds at random. This often yields robust performance with limited tuning effort, and it provides a useful non-boosting baseline for engineered-feature classification.

% In the implemented pipeline, the number of trees, depth limits, split constraints, and feature subsampling strategy are tuned under the shared HPO protocol. Class imbalance is handled via balanced class weights. Probability calibration, when enabled, follows the same validation-based sigmoid calibration procedure.
The ensemble of extremely randomised trees is built with \texttt{sklearn.ensemble.ExtraTreesClassifier}.
Random splits and random feature subsets yield lower bias than a conventional Random Forest and produce well‑calibrated probability estimates out of the box.
The estimator is configured with the following fixed parameters:

\begin{itemize}
    \item \texttt{random\_state} – fixed to the global seed for reproducibility.
    \item \texttt{class\_weight = "balanced"} – sklearn’s native inverse‑frequency weighting to handle class imbalance.
    \item \texttt{n\_jobs} – set to the resolved number of parallel jobs.
\end{itemize}

Hyper‑parameters are tuned via the same Optuna pipeline (50 trials, TPE sampler) or fall back to the midpoint of each range.
The search space (Table~\ref{tab:et_hp_space}) contains integer, categorical, and boolean domains; the suggestion parser interprets the explicit type specifications accordingly, applying a step of 100 for \texttt{n\_estimators} and sampling uniformly from the categorical sets.
