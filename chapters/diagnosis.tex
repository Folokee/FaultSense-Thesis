\chapter{Fault Diagnosis}\label{ch:fault-diagnosis}

\section{Introduction}
After an anomalous state is detected, the next step in an FDD workflow is to identify the most likely fault type. In this project, diagnosis is formulated as a supervised multi-class classification task over engineered features extracted from PV system measurements. Unlike the anomaly detection stage, labeled fault categories are available for training; the objective is to output a discrete fault class among $C=4$ predefined types.

\section{Task Formulation and Methodology}

\paragraph{Problem definition.}
Let $x \in \mathbb{R}^F$ be a feature vector computed from a PV time segment, and $y \in \{1,2,3,4\}$ the corresponding fault label. The diagnosis task learns $f_\theta: x \mapsto \hat{p}(y \mid x)$ and predicts $\hat{y} = \arg\max_c \hat{p}(c \mid x)$.

\paragraph{Evaluation protocol.}
Because fault classes are imbalanced in realistic PV logs (class~4 Shadowing: 1\,000 episodes; classes~1--3: 15--23 episodes), the primary evaluation metric is \textbf{macro-averaged F1-score} (macro F1), which assigns equal weight to each class regardless of how many samples it contains; this prevents the dominant Shadowing class from masking poor performance on minority faults. Per-class F1 and per-class PR-AUC are also reported. To obtain robust uncertainty estimates, hyperparameters are optimised \emph{once} on the original temporal holdout, then the winning configuration is retrained across $K=5$ folds using \texttt{StratifiedGroupKFold}: a cross-validation strategy that (i) keeps the class-proportion ratio roughly equal across folds (\emph{stratified}) and (ii) ensures that all time-series samples belonging to the same fault episode (\emph{group}) always fall in the same fold — preventing data leakage from an episode spanning the train/test boundary. All metrics are reported as mean~$\pm$~std over the five folds.

\paragraph{Feature profile.}
Diagnosis is performed on the \texttt{plus\_physics} feature profile (15 engineered features: raw electrical + physics-derived indicators). In contrast to Task~A, where a normalizing flow learns its own representations and hand-crafted features are redundant, tree ensembles cannot perform representation learning: they partition the input feature space directly. The discriminative power of the engineered features is therefore critical — as confirmed by the feature-importance analysis in Section~\ref{sec:diag-winner}.

\section{Shared Experimental Infrastructure}\label{sec:diag-shared-infra}

\paragraph{Probability calibration.}
A tree classifier's raw probability outputs are often overconfident (probabilities near 0 or 1) or underconfident. To make the output probabilities reliable for the confidence-based alerting logic of the operator dashboard, a calibration step is applied: after fitting the base classifier on the training partition, a \emph{sigmoid calibrator} (Platt scaling) is fitted on the held-out validation partition. Platt scaling fits a logistic (sigmoid) function on top of the raw model scores to align predicted probabilities with empirical frequencies — for example, ensuring that among samples assigned a 70\% confidence, approximately 70\% are truly of that class.

Calibration quality is quantified by four metrics, all computed on the held-out test set:
\begin{itemize}
    \item \textbf{Log-loss} (cross-entropy): the average $-\log \hat{p}(y)$ where $\hat{p}(y)$ is the predicted probability for the true class; lower is better, with 0 being perfect.
    \item \textbf{Brier score} (multiclass): the mean squared error between predicted probability vectors and one-hot true labels, averaged over classes; lower is better.
    \item \textbf{Expected Calibration Error (ECE)}: the confidence axis is divided into bins; for each bin, the gap between mean predicted confidence and mean actual accuracy is measured; ECE is the weighted average of these gaps. A perfectly calibrated model has ECE~=~0.
    \item \textbf{Maximum Calibration Error (MCE)}: the largest gap across all bins, capturing worst-case miscalibration.
\end{itemize}

\paragraph{Leakage checks.}
Before and after training, automated checks verify that no identical feature rows appear across train and validation partitions, and a full leakage report is run on the test partition.

\section{Model Lineup}

\subsection{LightGBM Classifier}

LightGBM builds gradient-boosted decision trees sequentially, where each tree corrects the residuals of the current ensemble. It applies histogram-based binning for efficient split search, making it fast to train on tabular data. Class imbalance is handled through balanced class weights; HPO is performed with Optuna TPE over 35 trials maximising validation macro~F1.

\subsection{ExtraTrees Classifier}

ExtraTrees (Extremely Randomised Trees) builds an ensemble of trees with strong randomisation: both the split variable and the split threshold are selected at random, then the best among $k$ candidates is chosen. This additional randomness acts as a regulariser, often yielding competitive performance with lower variance than standard random forests and without requiring complex hyperparameter tuning. Class imbalance is handled through balanced class weights.

\section{Discussion}\label{sec:diag-discussion}

\paragraph{The fold-3 hard split.}
All three classifiers exhibit a consistent performance drop on fold~3 (ExtraTrees: 0.820, CatBoost: 0.788, LightGBM: 0.766 vs $\sim$0.99 on the other four folds). The fold-3 test partition contains only 2 episodes from class~1 and 1 episode from class~2 — the smallest minority-class test representation across all folds. This drop is therefore a \textbf{data-structural artefact}, not a model instability: with $<$2 fault episodes in a class, even a perfect classifier is penalised by macro F1 if it correctly predicts the one episode but is scored against a two-episode baseline. The consistent drop across all three model families (gradient-boosting variants and a randomised tree ensemble) is precisely the evidence that this is a data-partition issue rather than a model deficiency. This motivates reporting mean~$\pm$~std over all five folds rather than cherry-picking a single split.

\paragraph{Why ExtraTrees wins.}
ExtraTrees achieves the highest macro F1 and the lowest fold-to-fold variance among the three models. The strong randomisation in threshold selection acts as an implicit regulariser that is particularly effective when the minority class episodes are few and diverse. Boosting methods (LightGBM, CatBoost) can overfit to the dominant class patterns when minority support is this sparse; ExtraTrees' independence between trees provides a more balanced boundary.

\paragraph{Where all models agree.}
Open-Circuit (cls~3) is correctly classified at near-perfect F1 across all three models and all five folds. Its spectral signature — a total string current drop combined with maintained irradiance — is unambiguous in the feature space. Shadowing (cls~4) is also easy due to its statistical dominance and characteristic partial-shading pattern.

\paragraph{The hardest class: Degradation (cls~2).}
Degradation is the hardest fault for both Task~A (anomaly detection) and Task~B (diagnosis). Its gradual drift overlaps the normal-operating manifold at low severity (Task~A), and in the classification space it confuses with Short-Circuit at partial severity (Task~B: cls~2 recall 0.982 but precision 0.797, suggesting contamination from cls~1). The high PR-AUC (0.970 for ExtraTrees) indicates that the ranking quality is good, but the decision boundary at the chosen threshold misses some low-severity instances.

\paragraph{Dual feature-profile conclusion.}
The Task~A and Task~B results together illustrate an important principle: \emph{the value of feature engineering depends on whether the model can learn its own representations}. Normalizing flows learn representations as part of density estimation; adding features hurts. Tree ensembles partition a fixed feature space; adding informative features helps. The \texttt{plus\_physics} feature profile is therefore the right choice for Task~B, and \texttt{baseline\_raw} is the right choice for Task~A — for complementary, model-family-driven reasons.

\paragraph{Calibration and deployment.}
Sigmoid calibration improves log-loss (0.063 → 0.059) with a negligible impact on macro F1 on the held-out test. The resulting probability outputs are suitable for the confidence-based tiered alerting logic of the operator dashboard (Chapter~\ref{ch:deployment}).
