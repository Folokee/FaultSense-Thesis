\chapter*{General Conclusion}
\addcontentsline{toc}{chapter}{General Conclusion}
\label{ch:conclusion}

This thesis set out to design, validate, and deploy a complete artificial-intelligence-based Fault Detection and Diagnosis (FDD) system for photovoltaic installations, grounded in real field data and operational under the constraints of embedded hardware. The three objectives stated in the General Introduction have been carried through to a working end-to-end system.

The first objective, a rigorous and reproducible data pipeline, was met through a staged architecture spanning ingestion, temporal splitting, preprocessing, and feature engineering. Each stage enforces an explicit leakage-prevention contract: segments are the atomic units of partitioning so that no operating episode crosses a partition boundary, partitions are assigned in strict temporal order, sliding windows are constructed only after the boundaries are fixed, and every statistic that informs cleaning or normalization is estimated from the training partition alone. On top of this foundation, a physics-informed feature representation encodes domain knowledge (irradiance-normalized channels, per-string imbalance descriptors, temperature-corrected power, and first-order temporal derivatives) that a purely data-driven model would otherwise have to rediscover from raw measurements.

The second objective, cost-effective models for the two diagnostic tasks, was addressed by treating detection and diagnosis as structurally distinct problems. Anomaly detection was formulated as a semi-supervised task in which the detector learns the normal operating manifold without exposure to labeled faults, with a uniform Generalized Pareto Distribution threshold-calibration policy applied across all detectors to ensure apples-to-apples comparison. The physics-conditioned normalizing-flow detector (PC-Flow) was selected for deployment on the strength of its per-class detection, attaining a test binary PR-AUC of $0.989 \pm 0.008$ and a worst-class PR-AUC of $0.968 \pm 0.018$ under five-fold episode-stratified cross-validation, together with a compact, stateless architecture of fewer than 25,000 parameters. Fault diagnosis was handled by gradient-boosted tree ensembles with native class weighting: on the Costa test set the selected CatBoost classifier reached 99.2\% accuracy and a macro-averaged F1 of 0.957 across the four fault classes, with per-class analysis confirming strong performance even on the harder degradation and short-circuit signatures rather than only on the majority classes. A leakage-validation suite (label-shuffle tests, duplicate checks, time-split integrity, and feature-importance audits) was run alongside every training stage so that no reported figure rests on an unverified assumption.

The third objective, edge deployment, was realized on an NVIDIA Jetson Nano. The trained models were exported to ONNX and executed with ONNX Runtime, governed by an artifact contract that enforces consistency between the training and inference environments at load time. The deployed system is wrapped in a real-time monitoring interface built as a Python backend and a web frontend communicating over WebSocket channels, exposing a three-tier ISA-18.2 alarm hierarchy (P3~Advisory, P2~High, P1~Critical) derived from sensitive, conformal, and CUSUM threshold policies on the same detector score, together with per-class fault diagnosis, an event log with PDF export, and a Page-Hinkley drift monitor that watches a physics channel independently of the model score and gates every model update behind explicit operator approval.

\section*{Limitations and Perspectives}

Several limitations bound the scope of these results. The evaluation rested on a single dataset recorded at a single site, with faults induced under controlled conditions; while this yields clean, electrically well-characterised fault signatures, it does not establish cross-site generalisation, nor does it sample the long tail of rarer degradation mechanisms encountered in the field. Furthermore, the dataset spans only four fault classes, leaving a substantial portion of the PV fault taxonomy unexplored. The system currently reports a fault label and a confidence score without any explanation of which measurements or features drove the decision; such interpretability would be valuable for operators seeking to understand the root cause of an alarm and to select an appropriate intervention. Finally, the solution has not yet been deployed on a real-world pilot installation, and its behaviour under genuine, uncontrolled field operating conditions remains an open question.

These limitations map directly onto the most promising directions for future work. A primary priority is the acquisition of a richer real-world dataset encompassing a wider variety of fault types and severities, recorded across multiple sites under diverse climatic conditions, to support robust cross-site generalisation. A second perspective concerns explainability: integrating feature attribution methods into the diagnostic pipeline would expose which input channels and physics descriptors drive each alarm, bridging the gap between model output and actionable operator understanding. Cross-plant transfer represents another promising avenue, enabling models trained on one installation to be adapted to another with minimal target-site data and thereby reducing the cold-start burden when deploying the system to new photovoltaic plants.
