\section{Détection d'anomalies}
% ════════════════════════════════════════════════════════════

\begin{frame}{Détection d'anomalies : formulation}
  \footnotesize
  Sous irradiance et température données, les mesures électriques normales suivent une relation physique attendue. Une panne est une \alert{déviation persistante} de cette relation, non explicable par $G$ ou $T$ :
  \[
    \mathbf{X}(t) = [\mathbf{x}(t-w+1), \ldots, \mathbf{x}(t)] \in \mathbb{R}^{w \times d}, \qquad
    d(t) = \mathbf{1}\!\left[s(\mathbf{X}(t)) > \tau\right]
  \]
\end{frame}

\begin{frame}{Choix de modélisation}
  \footnotesize
  \begin{itemize}
    \item \textbf{Défi} : les classes de panne sont trop rares et déséquilibrées pour apprendre un classifieur supervisé fiable.
    \item \textbf{Solution} : formuler le problème comme une détection \alert{semi-supervisée} (apprendre uniquement sur des fenêtres normales et évaluer sur toutes les fenêtres) pour minimiser la dépendance à l'annotation des classes de panne.
  \end{itemize}
\end{frame}

\begin{frame}{Détecteurs évalués}
  \footnotesize
  \begin{itemize}
    \item Online $\rightarrow$ Bayesian Online Changepoint Detection (BOCD)
    \item Kernel-based $\rightarrow$ One-Class Support Vector Machine (OC-SVM)
    \item Ensemble $\rightarrow$ Isolation Forest
    \item Sequence Modeling (DL) $\rightarrow$ Mamba Adaptive Anomaly Transformer (MAAT)
    \item Reconstruction-based (DL) $\rightarrow$ Gated Transformer-BiLSTM Anomaly Detector (GTBAD)
    \item Normalizing Flow (DL) $\rightarrow$ PC-Flow
  \end{itemize}
\end{frame}

\begin{frame}{Baselines classiques : principe}
  \footnotesize
  \begin{description}
    \item[BOCD] Maintient une distribution sur le \emph{run length} ; mise à jour récursive en streaming, sans fenêtre fixe. Anomalie = forte probabilité de changepoint.
    \item[Isolation Forest] Repose sur l'hypothèse que les anomalies sont \alert{rares et peu nombreuses}, donc plus faciles à isoler. Score = profondeur moyenne d'isolement sur des arbres de partitionnement aléatoire.
    \item[OC-SVM] Apprend une frontière (hyperplan dans l'espace à noyau) englobant la région normale. Noyau RBF : le \emph{kernel trick} calcule directement les produits scalaires d'un espace de dimension infinie, sans jamais le construire explicitement. Score = distance signée à la frontière.
  \end{description}
\end{frame}

\begin{frame}{Mamba Adaptive Anomaly Transformer (MAAT) : principe}
  \footnotesize
  \begin{itemize}
    \item Combine Mamba (selective state-space, séquence longue en temps linéaire) et le principe \emph{association-discrepancy} de l'Anomaly Transformer
    \item Une reconstruction pure ne regarde que l'erreur ponctuelle $\|x_t - \hat{x}_t\|^2$, sans tenir compte de la façon dont chaque instant se positionne dans la série
    \item \alert{Nouveau} : compare les poids de \emph{self-attention} entre pas de temps ($S$, issus de l'encodeur) à un prior gaussien local ($P$) -- normal = association globale, anomalie = association locale seulement
    \item Le score pondère l'erreur de reconstruction par cet écart $D_t = \mathrm{KL}(S\|P) + \mathrm{KL}(P\|S)$ : il amplifie l'erreur sur les instants dont le \emph{pattern d'association} est anormal, pas seulement ceux mal reconstruits
  \end{itemize}
  \vfill
  Variante adaptée de l'algorithme original (Sellam et al., 2025).
\end{frame}

\begin{frame}{Gated Transformer-BiLSTM Anomaly Detector (GTBAD) : principe}
  \begin{itemize}

    \item Apprend à reconstruire les motifs de fonctionnement normal
    \item Anomalie = erreur de reconstruction
  \end{itemize}

\begin{frame}{PC-Flow : principe}
  \footnotesize
  Caractériser le fonctionnement normal revient à estimer sa distribution de probabilité $p(x)$ : un problème de \alert{density estimation}.
  \begin{itemize}[<+->]
    \item Cette distribution n'est pas simple : les mesures réelles suivent une forme complexe, pas une gaussienne
    \item Un \alert{normalizing flow} apprend une transformation $f_\theta$ \alert{parfaitement réversible} qui ramène cette distribution complexe vers une gaussienne simple
    \item Réversible $\Rightarrow$ probabilité \alert{exacte} pour n'importe quel point, sans approximation
    \item Score d'anomalie = à quel point l'échantillon est improbable sous la distribution apprise
  \end{itemize}
\end{frame}

\begin{frame}{Probabilité marginale vs conditionnelle}
  \footnotesize
  Les normalizing flows existants apprennent une probabilité \alert{marginale} $p(x)$ : une seule distribution du normal, valable à tout instant.
  \[
    \underbrace{p(x)}_{\text{flow classique}} \qquad \longrightarrow \qquad \underbrace{p(x \mid c)}_{\text{PC-Flow}}, \quad c = (\text{irradiance}, T_{\text{PV}})
  \]
  \begin{itemize}[<+->]
    \item Cycle \alert{diurne} fort (irradiance, température) : une même puissance peut être normale ou suspecte selon le moment
    \item Probabilité marginale $\Rightarrow$ confond changement de régime et panne
    \item \alert{La solution} : conditionner sur $c$ -- jugement relatif au régime, pas à une moyenne globale
  \end{itemize}
\end{frame}

\begin{frame}{Ranking quality : de quoi parle-t-on ?}
  \footnotesize
  \begin{itemize}
    \item F1, precision, recall sont figés à un seuil unique $\tau$ -- ils ne mesurent qu'un seul point de fonctionnement
    \item Le \alert{ranking quality} évalue si le détecteur ordonne correctement les échantillons par score d'anomalie, sur \emph{tous} les seuils possibles -- d'où son caractère \emph{threshold-free}
    \item Nécessaire ici : le choix du modèle (étape 1 du protocole) précède tout choix de seuil (étape 4)
  \end{itemize}
\end{frame}

\begin{frame}{PR-AUC : la métrique retenue}
  \footnotesize
  \[
    \mathrm{Precision} = \frac{TP}{TP+FP}, \qquad \mathrm{Recall} = \frac{TP}{TP+FN}, \qquad \mathrm{PR\text{-}AUC} = \int_0^1 \mathrm{Precision}(r)\,\mathrm{d}r
  \]
  PR-AUC est l'aire sous la courbe precision-recall : elle résume, sur tous les seuils, la precision que le détecteur conserve à chaque niveau de recall.
\end{frame}

\begin{frame}{Pourquoi PR-AUC (et pas ROC-AUC) ?}
  \footnotesize
  \begin{itemize}
    \item La phase d'EDA a montré $\approx$84,7\% de lignes normales / $\approx$15,3\% en panne, et parmi les pannes, un facteur $\approx$30$\times$ entre la classe la plus rare (Short-Circuit, 5\,999) et la plus fréquente (Shadowing, 184\,311) -- severe class imbalance, à deux niveaux
    \item PR-AUC se base uniquement sur precision et recall de la classe positive (la panne) -- sensible à l'imbalance, contrairement à ROC-AUC
    \item \alert{Macro PR-AUC} : moyenne non pondérée par classe -- Shadowing ne domine plus le score, chaque fault class compte autant
  \end{itemize}
\end{frame}

\begin{frame}{Annexe B --- Justification du macro PR-AUC}
  \footnotesize
  \[
    \mathrm{PR\text{-}AUC}_{\mathrm{macro}} = \frac{1}{K}\sum_{k=1}^{K} \mathrm{PR\text{-}AUC}_k, \qquad K = 4
  \]
  \begin{itemize}
    \item Le binary PR-AUC pondère implicitement par la fréquence -- Shadowing (35,7\% des lignes en panne) domine le calcul
    \item Le macro PR-AUC donne un poids \alert{égal} à chaque classe, indépendamment de sa fréquence
    \item Une panne rare (Short-Circuit, 15 épisodes) compte autant qu'une panne fréquente (Shadowing, 1000 épisodes)
    \item Cohérent avec l'objectif opérationnel : un détecteur aveugle à une panne rare reste inacceptable même s'il excelle sur la panne fréquente
  \end{itemize}
\end{frame}

\begin{frame}{Annexe E --- MCE = 0,754, explication}
  \footnotesize
  \begin{itemize}
    \item Le MCE capture l'écart \alert{pire-cas} entre confiance prédite et exactitude observée, sur un seul bin de confiance
    \item À ne pas confondre avec l'ECE (0,019), qui moyenne cet écart sur \emph{tous} les bins, pondéré par leur population
    \item Le bin concerné est un bin de très haute confiance et de très faible population (\og tail-bin effect \fg) -- quelques échantillons mal classés y suffisent à produire un grand écart relatif
    \item Log-loss (0,059) et Brier (0,008) confirment que la qualité \emph{globale} de calibration reste excellente
  \end{itemize}
\end{frame}

\begin{frame}{Annexe F --- Protocole de Drift opérationnel}
  \footnotesize
  Test \texttt{Page-Hinkley} bidirectionnel sur les statistiques journalières du régime opératoire $(\mathrm{irr}, T_{PV})$ :
  \[
    M_t = \sum_{i=1}^{t}(x_i - \bar{x} - \delta), \quad \mathrm{PH}_t = M_t - \min_{j\le t} M_j, \quad \text{drift} = \mathbf{1}[\mathrm{PH}_t > \lambda]
  \]
  \begin{itemize}
    \item Agrégation \alert{journalière} : distingue le drift saisonnier persistant du cycle diurne attendu
    \item Stade \textbf{advisory} après 7 jours consécutifs de glissement
    \item Stade \textbf{action-ready} après 14 jours consécutifs
    \item Surveille le \emph{régime}, indépendamment du score du modèle -- évite la circularité (cf.\ feedback circularité \& gates)
  \end{itemize}
\end{frame}

\begin{frame}{Annexe I : Justification métrique ranking quality}
  \footnotesize
  \begin{itemize}
    \item ROC-AUC compare true positive rate et false positive rate -- sur Costa ($\approx$84,7\% normal), le grand nombre de negatives maintient le false positive rate artificiellement bas
    \item Un détecteur médiocre peut donc afficher un ROC-AUC élevé sans réellement bien séparer les classes de panne
    \item PR-AUC se base uniquement sur precision et recall de la classe positive (la panne) -- aucune dépendance au nombre de negatives
    \item C'est pourquoi PR-AUC (et non ROC-AUC) sert de critère de ranking quality dans le protocole d'évaluation
  \end{itemize}
\end{frame}
